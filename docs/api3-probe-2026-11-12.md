# api3 probe, 2026-11-12

Flow PT 8.91, shotgun_api3 3.10.5, one script user with `generate_event_log_entries` true. Writes:
throwaway `zzprobe mockgun` fields on Version (all deleted, names spent) and one Version in a sandbox
project (created, updated, deleted, revived, deleted). Ids, project and user are replaced with
placeholders. sg-groundtruth recorded the same behaviour over REST (findings 019, 025, 040, 049);
this file is the api3 wording mockgun reproduces.

## Schema field writes

| call | answer |
|---|---|
| `schema_field_create("Version", "text", "zzprobe mockgun a")` | `"sg_zzprobe_mockgun_a"` |
| same again | `"sg_zzprobe_mockgun_a_1"`, no error |
| `schema_field_create("Version", "number", "sg_zzprobe mockgun b")` | `"sg_sg_zzprobe_mockgun_b"` |
| type `calculated`, no properties | Fault `API schema_field_create() NoMethodError: undefined method 'strip' for nil` |
| type `query`, `summary`, `color`, `image`, `nope` | Fault `API schema_field_create() can't create '<type>' data type.  Valid data types:` + the list below |
| type `entity`, no `valid_types` | Fault `API schema_field_create() missing required 'properties' ["valid_types"]` |
| type `checkbox`, no `default_value` | Fault `API schema_field_create() Crud::ParameterError: Only true or false allowed in checkbox` |
| entity type `NotAType` | Fault `API schema_field_create() invalid/missing string entity 'type':` + the request + `Valid entity types:` + every entity type |
| `schema_field_update(..., {"data_type": "number"})` | Fault `API schema_field_update() invalid property 'data_type':` + `{"property_name" => "data_type", "value" => "number"}` + `Valid property names:` + `["name", "visible", "description", "summary_default", "custom_metadata", "unique"]` one per line |
| raw `schema_field_update` with `data_type` top level and empty `properties` | Fault `API schema_field_update() can't create/update with no 'properties':` + `[]` |
| `schema_field_update(..., {"name": ...})` | `True` |
| update, read or delete of a field that does not exist | Fault `API schema_field_<call>() Version.<code> doesn't exist:` + the request |
| `schema_field_delete` | `True` |
| create the deleted field's display name again, as `text` or `number` | Fault `API schema_field_create() failed, there is a retired field with the same field_name: <code>. Delete the retired field forever from the Trash Page in Shotgun and try again.` |
| raw `_call_rpc("schema_field_revive", ...)` | Fault `Error: API method "schema_field_revive" is not permitted.` |

## Revive from an api3 session, over REST

api3 has no field revive, but the same credentials reach REST. Recorded later the same day:

```
sg.get_session_token()                                     -> a session token
POST /api/v1/auth/access_token
     grant_type=session_token, session_token=<token>      -> 200 {token_type, access_token, expires_in, refresh_token}
POST /api/v1/schema/Version/fields/sg_sg_zzprobe_mockgun_b
     {"revive": true}, Bearer <access_token>               -> 204, empty body
sg.schema_field_read("Version", "sg_sg_zzprobe_mockgun_b") -> data_type number (its original type), name kept
sg.schema_field_delete(...)                                -> True (trashed again)
```

Events for the revive:

```
Shotgun_DisplayColumn_Change    attribute retirement_date, meta old_value "2026-11-12 21:54:12 UTC", new_value null
Shotgun_DisplayColumn_Revival   meta {class_name: DisplayColumn, display_name: <code>, id: <dc>, entity_type: DisplayColumn,
                                      entity_id: <dc>, type: entity_revival}
                                description ' revived DisplayColumn "<code>"'
```

`client_credentials` with the script name and key mints the same kind of token (sg-groundtruth
endpoint card post_auth_access_token). Field revive semantics: finding 040.
